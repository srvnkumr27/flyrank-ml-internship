Predicting Next-Day Search Clicks for Content Refresh Prioritization

A time-aware machine-learning study using anonymized search-performance data to investigate whether recent signals can support a ranked content-review queue.

March 2026 · 3.43M processed observations · Regression · Decision support

Abstract Problem Data Method Results Limitations Recommendations Reproducibility

01 · Abstract

This study asks whether recent search-performance signals can estimate a page's next-day clicks well enough to support a ranked content-refresh queue. Using a processed March 2026 panel derived from the FlyRank internship search-data release, I constructed seven-day historical features for clicks, impressions, ranking position and CTR, together with a calendar feature. I compared a transparent seven-day-average baseline with Decision Tree, Random Forest and Gradient Boosting regression models using a chronological train/validation split and explicit leakage checks. On the March 25–30 validation window, the seven-day-average baseline achieved an RMSE of approximately 0.7904 and outperformed the tested tree-based models, meaning the current ML feature set did not demonstrate an improvement over the simple baseline. The result supports using the current pipeline as decision-support and prioritization infrastructure while avoiding causal claims about whether a content refresh will increase search traffic.

02 · Introduction / Problem Statement

SEO and content teams may have thousands of pages competing for limited review capacity. The practical question is not simply which pages have traffic, but which pages should be investigated first.

This project turns recent search telemetry into a prediction and prioritization workflow:

Search signals → historical features → next-day click estimate → review priority → human decision
Important: The system recommends what to investigate. It does not automatically change content or establish that a change will cause additional traffic.

Training: March 1–24, 2026   |   Validation: March 25–30, 2026

A chronological split was used instead of a random row split so future observations do not leak into training.

Leakage checks

target_next_day_clicks and the intentionally constructed future feature trap_next_day_impressions were excluded from predictive inputs. Earlier leakage testing showed that future information can produce suspiciously strong performance, confirming the need for strict temporal feature construction.

05 · Results

MAIN FINDING

The simple baseline wins.

None of the tested tree-based ML models improved on the seven-day-average baseline on the held-out March 25–30 validation window.

MethodMAE ↓RMSE ↓R² ↑
7-day average baseline0.20940.79040.6852
Decision Tree0.22660.87620.6132

Gradient Boosting0.22510.82170.6597

Gradient Boosting is the strongest of the tested ML models, but it still does not beat the historical baseline. Therefore, the current feature set does not justify replacing the simpler predictor.

06 · Limitations & Honest Framing

Observational

Search behavior is observed; no intervention experiment is run.

Not causal

Prediction does not establish that refreshing content causes more clicks.

Not Google prediction

The system does not model or reverse-engineer a search ranking algorithm.

Limited window

The reported validation covers March 25–30, 2026.

Feature limitations

The current feature set focuses mainly on recent search-performance signals.

Baseline strength

The simple baseline currently outperforms the tested ML models.
